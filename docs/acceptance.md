# T81: локальная приёмка

Статус: **IN-PROGRESS**, T41 не закрыта. Пакет устанавливается локально;
это не публикация и не завершённая приёмка всех заявленных платформ.

## Стенд и границы измерений

2026-09-18, Linux, VSCodium 1.109.5, Extension Host Node 22.21.1,
CLI Node 22.23.1, Bun 1.4.2. Backend eska 0.10.0 из `feat/ide` (`5f2da24`),
собран `cargo build --profile dist`. VSIX `1c-tooling.eska-explorer@0.0.0`.
Intel Core i5-13420H, 12 логических CPU. Установленный пакет загружен в test mode;
runtime код берётся из каталога установки, а не из `out` рабочей копии.

Пять свежих процессов backend в одном Extension Host. Существующий дисковый кеш
сохранён, кеш ОС не сбрасывается; «cold» здесь означает новую сессию backend,
а не пустой дисковый кеш. Начальная индексация измеряется отдельно от готового
поиска. Тест не обходит XML в клиенте, не вызывает ibcmd/Конфигуратор.
Во время финальной серии не запускались сборки и хеширование стенда.

Использованы реальные provider, TreeView.reveal, Quick Pick и команды редактора.
Время заканчивается при завершении native API/обновлении модели Quick Pick:
это **не измерение времени показа последнего пикселя** и не эмуляция клика мышью.
Выбор, открытие исходников и фильтр измеряются отдельными сериями. Первая пробная
серия чередовала выбор с перерисовкой корня и давала p95 447 мс; её не смешиваем
с выбором без обновления. Это известная задержка сценария «фильтр → выбор»,
требующая отдельной визуальной проверки.

## Память и бюджеты

Максимальный VmHWM backend — 193.1 MiB; Extension Host — 315.0 MiB.
Здесь учитывается весь процесс Extension Host, включая нативные объекты IDE,
открываемые редакторы и тестовый runner. Складывать эти максимумы как точный
одновременный пик нельзя: они получены не синхронным семплированием.
Текущий RSS Extension Host после отключений: 258.8, 264.7, 260.0, 267.0, 268.8 MiB.
Пять циклов не доказывают отсутствие утечек: нужен более длинный прогон и анализ
удерживаемых объектов, если рост продолжится.

Бюджеты T68 backend нельзя выдавать за выполненные интерфейсом. Выбор через
TreeView.reveal укладывается в 20 мс, отдельный запрос поиска — в 50 мс.
Quick Pick намеренно ждёт 250 мс после ввода; полная выдача занимает p95 286 мс.
Открытие BSL имеет p95 346 мс; общий модуль иногда велик, редактор читает сам файл.
Первое раскрытие тысяч объектов и фильтр также имеют отдельные расходы IDE.
Предел 256 MiB для Extension Host не выполнен. Эти результаты требуют отдельного
решения по UI-бюджетам/оптимизации; текущий отчёт не повышает бюджеты задним числом.

## Воспроизведение

Подготовьте VSIX по [инструкции упаковки](packaging.md), затем:

```sh
ESKA_TEST_BINARY="$(realpath ../eska/target/dist/eska)" \
ESKA_TEST_VSIX="$PWD/eska-explorer-0.0.0.vsix" \
ESKA_PERF_PROJECT="$(realpath ../eska-playground/big_configuration_temp)" \
ESKA_PERF_RESULT=/tmp/eska-performance.json \
VSCODE_EXECUTABLE=codium node test/run-host.mjs test/performance-host.cjs
```

Большой проект задаётся явно, исходники не изменяются; workspace и настройки
создаются во временном каталоге runner. Backend может обновить производный кеш.
RSS sampler использует Linux `/proc`; на других ОС потребуется другой измеритель.
[Неокруглённые результаты финальной серии](measurements/t81-linux.json).

Полный native-тест сначала останавливался на поиске: Quick Pick успевал закрыться
при потере фокуса тестового окна (`disposed:true`). В тесте установлен
`ignoreFocusOut=true`; production-поведение не менялось. Финальный запуск прошёл,
включая клавиатурное сворачивание модулей и сохранение состояния. Проверка закрытия
по потере OS-фокуса этим запуском не покрывается.

## Совместимость с bsl-analyzer

В изолированный каталог скопирована установленная версия расширения 0.1.12,
сервер `bsl-analyzer-app` 0.2.79 задан явным путём, автозагрузка сервера исключена.
До подключения Explorer проверены непустая выдача подсказок, правки форматтера
и синтаксические ошибки в принадлежащем тесту BSL. После подключения и перехода
из дерева результаты совпали. Файл настроек с выбранным BSL-форматтером сохранился
побайтно. На большой конфигурации analyzer не запускался.

Локальный экземпляр пользователя регистрирует debug type `bsl-dummy`; тест проверил
его сохранность и отсутствие debugger contribution у Explorer. Это не проверка
настоящего attach к 1С и не доказательство работы всех версий bsl-analyzer.
Для отладочной приёмки нужен отдельный сеанс с платформой, без сборки большого стенда.

```sh
ESKA_TEST_BINARY="$(realpath ../eska/target/dist/eska)" \
ESKA_TEST_VSIX="$PWD/eska-explorer-0.0.0.vsix" \
ESKA_BSL_EXTENSION=/absolute/path/to/installed/bsl-analyzer-extension \
ESKA_BSL_BINARY="$(command -v bsl-analyzer-app)" \
VSCODE_EXECUTABLE=codium node test/run-host.mjs test/compatibility-host.cjs
```

## Реальная установка CLI на Linux — 2026-09-19

Проверка выполнялась на Linux x86-64 через `bootstrapCommand` и `inspectGlobal`
из скомпилированного production-кода расширения. Использованы официальные
`eska-installer.sh` из GitHub Assets релизов 0.10.1 и 0.11.0.
SHA-256 установщика 0.11.0:
`eab7659fc01519f04f4218cfc7565ce8911805fee9a92e512d20d600559d054f`.

| Сценарий | Результат |
| --- | --- |
| Чистая установка 0.11.0 | Успех; глобальная CLI найдена, IDE handshake принят |
| Определение установленной 0.10.1 | Версия распознана, совместимость отклонена |
| Bootstrap 0.10.1 → 0.11.0 | Успех; каталог сохранён, новая CLI совместима |
| PATH | В тестовом `.profile` добавлено подключение `.eska/bin/env` |
| Receipt | Версия 0.11.0, `install_layout: flat`, prefix = тестовый `~/.eska/bin` |
| `selfUpdate` опубликованной 0.11.0 | Отсутствует, корректно распознано как false |

Для каждого сценария создан отдельный временный home в соседнем
`eska-playground`; HOME/XDG_CONFIG_HOME заданы только дочернему процессу.
PATH ограничен системными утилитами, поиск установленной CLI использовал fallback
`~/.eska/bin`. После проверки временные каталоги удалены. Пользовательская ESKA,
настройки оболочки и большая конфигурация не изменялись.

Полный вызов `eska update` с настоящей сменой версии не подтверждён.
Опубликованная 0.11.0 ещё не содержит команду. Текущая debug-сборка, скопированная
только в тестовую установку с настоящим receipt, вернула на `update --check
--format json` код 1 и `{"schemaVersion":1,"status":"error","code":"network"}`.
GitHub API отвечал HTTP 403, при этом скачивание Assets работало.

Здесь проверен реальный subprocess установщика, без нативного UI VS Code Tasks.
Cargo-обновление, полное self-update и Windows/macOS требуют отдельной приёмки.

## Самообновление и индекс Cargo после релиза 0.11.1

В одноразовой официальной установке development-сборка 0.11.0 с командой
`update` обновилась до настоящего опубликованного бинарника 0.11.1. Проверены
`update-available`, отсутствие записи при `--check`, `updated`, новая версия
и receipt. Уже опубликованная 0.11.1 вернула `up-to-date` в RU/EN и при повторном
update без изменения SHA-256 файла. JSON метаданных GitHub передавался без
изменений через локальный `gh api`-посредник из-за 403 неавторизованного API;
installer и бинарник скачивались из настоящих GitHub Assets.

У Cargo обнаружена отдельная ошибка: Web API crates.io отвечал 403, хотя
установка Cargo работала. Проверка публикации в CLI и bootstrap Explorer
переведена на официальный sparse index. Реальный `fetchText`/`assertCargoRelease`
успешно подтвердил опубликованную 0.11.1. Тесты покрывают yanked, чужой пакет,
неопубликованную версию, повреждённый индекс и неизвестную схему.

После исправления real Cargo-сценарий также прошёл: временная установка
0.11.0, тестовая development-сборка с исправлением, `update-available`,
настоящая установка 0.11.1 через `eska update`, статус `updated`. Root, profile
`dev`, target и feature-флаги сохранились. Проверка `up-to-date` выполнена
отдельно исправленной сборкой 0.11.1; опубликованная версия пока использует
прежний Web API и требует следующего релиза с исправлением. Пользовательская
CLI и версии репозиториев не изменялись.

TypeScript, 58 тестов Bun и 58 тестов Node прошли. Первый Node-прогон при
параллельной Cargo-компиляции имел два таймаута 150 мс в прежних transport-тестах;
повтор всего набора без компиляции прошёл. VSIX собран и проверен по составу.
