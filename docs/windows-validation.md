## Изменения

- Скрытие выбранной пустой группы сохраняет выбор до асинхронного изменения
  настроек и возвращает его к корню проекта после обновления дерева.
- Физические пути участников и sources сравниваются средствами native path API:
  варианты `C:`/`c:` не создают повторные файловые ветки и не ломают reveal.
  Добавлена Windows-регрессия с разными представлениями одного пути.
- Перед привязкой metadata generation обрабатываются накопленные файловые события.
  При сохранении native parent владелец запроса разрешается заново до открытия
  документа. Повторяться может только чтение владельца; создание документа,
  сессии и применение изменений выполняются однократно.
- Git-декорации после файлового события обновляют только инвалидированных предков
  выбранного узла. Временный `unknown_node` больше не кэшируется как отсутствие
  изменений; modified/staged/untracked, форма, удаление и переключение настроек
  проверены без запуска полного индекса.
- При раскрытии пути к активному файлу сначала завершается раскрытие корня.
  Это устраняет потерю выделения в холодном Windows workbench; dirty buffer,
  версия документа и исходники остаются прежними, полный индекс не запускается.
  Такой же барьер применён к переходу из поиска: его первое выделение больше
  не теряется при первоначальном отображении дерева.
  Переход ждёт публикации корней текущей модели и читает только верхний уровень
  целевого проекта. Две известные ошибки готовности native-корня ожидаются не более
  пяти секунд с передачей управления очереди; source lookup, выбор и изменения
  не повторяются. Смена модели и shutdown освобождают ожидание. Шесть холодных
  поисков прошли; в пяти журнал зафиксировал настоящий native miss и восстановление.
  Fault injection проверил постоянный отказ по лимиту и отсутствие повторов
  посторонних ошибок.
- BSL selector использует `Uri.fsPath`, как и редактор. Чтение ожидает проверки
  конфигурации; временно пустой outline больше не попадает в кэш VS Code.
  Отмена, остановка, изменение версии и закрытие документа прекращают ожидание.
- Windows file URI в LSP синхронизируются в стандартном представлении с диском.
  Native `c%3A` и upstream `C:` адресуют один документ, поток и проекцию;
  проверка версий правок сохраняется. Остальные схемы и ОС не меняются.
- После проекции отдельно учитываются версия LSP и версия native документа.
  Правка разрешена только для последнего синхронизированного native снимка;
  активная проекция, новый несинхронизированный текст и другой объект документа
  не имеют такого разрешения. Дополнительные копии текста не хранятся.
- Outline защищённого документа обновляет регистрацию при готовности native
  провайдера и изменении скрытого источника. Запись, переименование native alias
  и исполняемые code actions анализатора остаются запрещены.
- Обновление состояния свойств восстанавливает caret только в активном webview.
  Оно сохраняет фокус открытого native picker; выбранная ссылка автоматически
  записывается после фоновой проверки XML. Регрессия принудительно публикует
  свойства при открытом picker и проверяет реальный pointer выбор и Undo.
- Защита несохранённого XML сравнивает физические пути через native
  `path.relative`, включая разные регистры буквы диска. Нативная регрессия
  проверила сохранность файла и dirty buffer; прежний код её не проходил.
- Принятое в picker значение ожидает последнюю фоновую проверку XML и затем
  записывается однократно. Конфликт сохраняет черновик и блокирует запись;
  отмена, явная блокировка и смена соединения не выпускают отложенные правки.
  Enter и последующий blur уже записанного значения не создают вторую запись.
  Нативный тест удерживает настоящий ответ backend до подтверждения диалога.
- Применение BSL-запроса обновляет версию владельца отдельно от виртуального
  файла черновика. Его последующее закрытие больше не получает `File Modified
  Since`, когда многострочный CRLF-черновик ещё требует native Save.
  СКД проверена через реальное применение, Undo/Redo и единичную отмену в BSL;
  сравнение текста учитывает EOL документа, исходный файл на диске сохраняется.
- Нативный runner запускает Windows CLI через `Code.exe` и `cli.js` с
  `ELECTRON_RUN_AS_NODE=1`. GUI запускается отдельно. Настройки backend
  передаются до activation; первый запуск регистрирует language pack,
  следующие требуют фактический `vscode.env.language` ru/en.
- Удалён `--wait` при прямом GUI-запуске; окончание определяется выходом
  принадлежащего тесту workbench и результатом suite. Освобождаются унаследованные
  pipes Windows crash reporter; удаление собственного профиля имеет bounded retry.
- Тесты завершают backend до удаления fixtures, используют `.exe`, UTF-8 JSON,
  Unicode-каталоги и NTFS junction без привилегии создания file symlink.
- UI-сценарии ждут актуальные tree rows, готовность webview buttons и отдельные
  подтверждения native focus/tab/selection. Support migration test использует
  ту же serial queue, что production decoration requests.

В соседнем `eska` исправлены Windows manifest paths, recovery prefix/root,
локальные Git-пути, HTTPS TLS и запуск настоящей 1С с Win32 paths.
Пути внешней configuration reference преобразуются в обычные drive/UNC paths;
переход из native BSL в исходник БСП проверен настоящим LSP.
На Windows неявная политика analyzer использует встроенные факты API;
явная политика справки проекта сохраняется. Это устраняет зависание upstream
при автозагрузке установленного HBK. Machine-readable протоколы сохранены.
Изменён экспериментальный Rust field
`ContextDiscoveryError::Manifest.source: Box<ManifestConfigError>`.

не включён. Backend recovery, конфликт снимков и offline input дополнительно

## Повторная проверка

Команды PowerShell и переменные native host описаны в
[development.md](development.md#windows-powershell). Нужны абсолютные пути
к `eska-project.exe`, `eska-fmt.exe`, analyzer, `Code.exe`, его `cli.js` и VSIX.
Не запускайте rebuild executable, пока его использует тест: Windows держит
отображённый файл заблокированным. Для длительных проверок можно использовать
отдельную неизменяемую копию backend. UI-профили запускаются последовательно.

Для Node можно задать `--test-concurrency=2`; полного дополнительного скачивания
Electron runner не требует. `ESKA_HOST_NORMAL=1` и `ESKA_HOST_RESTART=1`
используют приватный startup probe в обычном установленном workbench.

## Ограничения

На настоящей Windows 1С **8.3.27.2342** в соседнем ESKA прошли CF/CFE/EPF/ERF,
повторная сборка, unpack/clean, восемь ru/en сценариев new/import/init,
console cancellation и roundtrip запросов СКД/динамического списка.
Само исполнение запросов не проверялось. Native patch остаётся закреплённым
на 8.3.27.2325 и корректно отвергает установленную 2342.
macOS, Remote, браузерные/виртуальные workspace, визуальный редактор форм и
отладчик не входят в этот результат. Эта серия не закрывает общую матрицу
T55/T81 и не является performance gate release-сборки.

Изменения сохранены в task branch. Публикация VSIX/релиза и изменение
существующих пользовательских demo не выполнялись.

## Установленный комплект

Шесть исправленных CLI находятся в `%USERPROFILE%/.eska/bin`, analyzer —
в `%USERPROFILE%/.eska/analyzer/bin`, с проверенными receipts и notices.
Переносимый VS Code и отдельный профиль находятся в
`%USERPROFILE%/Tools/eska-windows/VSCode`; VSIX и русский language pack установлены.
Профиль явно выбирает эти executable, включает language features и formatter.
Пользовательский PATH сохранён и дополнен; ярлык `ESKA VS Code` на рабочем столе
открывает отдельный demo в соседнем playground.

Проверен уже установленный комплект: validate/context, `eska fmt`, подготовка
конфига анализатора, fmt apply/check, Git status и `eska-check` exit 0.
Исходники пользователя и существующие demo не затрагивались.
