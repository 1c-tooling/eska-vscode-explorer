# Запросы в Designer XML и BSL

Выгрузка Designer XML остаётся исходником проекта. Запрос открывается отдельной
SDBL-вкладкой; дополнительный `.sdbl` в проекте не создаётся. Для этой возможности
нужна сборка `eska-project` с Metadata API 1.16 и capability `querySessions`
с устойчивым журналом применения. С API 1.12–1.15 дерево, свойства и обычный
BSL-клиент продолжают работать; с 1.14 доступно чтение прежних черновиков.

В дереве раскройте макет СКД, затем набор данных типа «Запрос» и строку **Запрос**.
Для формы раскройте реквизит ручного динамического списка и его запрос.
Имена наборов включают путь внутри объединения. Автоматический список без
сохранённого произвольного запроса не получает пустую редактируемую заготовку.

Во вкладке виден чистый SDBL: без XML entities и CDATA. Пакет остаётся целым.
Базовая подсветка работает без анализатора. Для XML контекстный анализ пока
недоступен. Для BSL ниже описаны отдельный режим применения и общий LSP-мост.
Конструктор с Metadata API 1.21 описан ниже.

**Ctrl+S** меняет только выбранный запрос в XML и возвращает XML вместо запроса.
Если исходный XML чистый, он сохраняется. Один Undo в XML отменяет правку
запроса. Остальные файлы не сохраняются. Для исходной dirty-вкладки перед
переходом действует штатный диалог IDE; отмена не открывает запрос.

У одного XML-владельца одна активная сессия. Повторное открытие того же запроса
переводит фокус в неё. Перед переходом к другому набору изменённая вкладка
проходит обычное предложение редактора сохранить, отбросить или отменить закрытие.
Правила поддержки 1С остаются обязательными; запрещённый источник доступен для чтения.

При изменении владельца, его дескриптора, приложения или прав сохранение
останавливается. Текст черновика остаётся во вкладке. Кнопка **Сравнить исходник
владельца** открывает сохранённый снимок исходного буфера и текущий XML.
Обе стороны сравнения доступны только для чтения. При неоднозначном переносе исходного
XML-комментария правка также не применяется. Команда **Назначить позиции исходных
комментариев** позволяет для каждого исходного комментария выбрать
автоматический перенос, текущий курсор, позицию `строка:столбец` (с единицы)
или явное удаление. После выбора продолжите приостановленный черновик и
повторите сохранение. Для комментариев между строками BSL допустимо начало
следующей строки запроса. Позиции проверяет ESKA; неверная позиция не означает
удаление комментария. Изменение запроса или владельца сбрасывает привязку выбора.

Черновики и полный исходный буфер владельца сохраняет ESKA через общий RPC
в личном каталоге расширения вне проекта. ESKA проверяет формат и квоты,
атомарно записывает checkpoint и сравнивает его подтверждённую ревизию.
Другое окно не может незаметно перезаписать или удалить изменённый checkpoint.
Прежний JSON/base64 формат T101 читается без конвертации. Расширение передаёт
изменённые части ограниченными chunks и ждёт подтверждения перед остановкой
backend. Клиентской файловой реализации восстановления больше нет.

Открытие, продолжение и подготовка применения выполняются общей моделью сессии
ESKA. Она проверяет источник, дескриптор, приложение, права, версии и точный
текст владельца. Расширение передаёт факты нативного документа, выполняет
проверенный план одной правкой и подтверждает фактический результат. Разбор
XML, перепривязка исходника и решения о восстановлении в адаптере не дублируются.

Пока сессия открыта, ESKA блокирует конкурирующую запись её исходника и
XML-дескриптора через свойства, Undo/Redo и переименование. Предпросмотр
переименования показывает причину запрета. Закройте сессию перед такой операцией.
Это ограничение операций backend; оно не меняет права ОС или настройки IDE.
С Metadata API 1.17 тот же запрет проверяется перед языковыми правками Explorer,
включая пользовательское отключение обычной защиты поддержки. Подготовленное
до открытия сессии разрешение нельзя повторно использовать после смены владения.
Обычный провайдер `eska-protected:` также получает снимок из ESKA. При активной
сессии backend возвращает весь удерживаемый dirty-текст родителя; более новый
буфер обычной вкладки не подменяет этот снимок. После закрытия сессии представление
снова следует текущему native-буферу или диску. Просмотр не продлевает владение
и не является подтверждением блокировки обычного BSL-редактора.

До правки владельца ESKA сохраняет намерение применения в личном журнале.
Если подтверждение прервалось после записи XML, следующая явная команда
продолжения сверяет исходный и ожидаемый результаты. Она не повторяет правку
автоматически. Новый ввод в SDBL во время сохранения остаётся отдельным
несохранённым черновиком и не теряется при подтверждении предыдущей версии.

После перезапуска открытие того же запроса возвращает
черновик как несохранённый документ. Кнопка **Продолжить черновик запроса** заново
проверяет приложение, владельца и права. До этого Ctrl+S и autosave не применяют
восстановленный текст. Если XML был отдельно сохранён и его содержимое полностью
совпадает с проверенным буфером, сессию также можно продолжить этой кнопкой.
Не совпадающий с исходным снимком XML не перезаписывается автоматически.

Журнал доступен после подключения backend даже при повреждённом `eska.toml`
и ошибке открытия метаданных: можно прочитать черновик и сохранённый снимок
владельца. Применение требует исправленного проекта и повторной проверки.
После явного отключения backend новые правки временно остаются в модели IDE;
при подключении они сверяются с подтверждённой ревизией. Для записи private
checkpoint нужен работающий backend. Чистая вкладка, закрытая при отключении,
удаляется из журнала после следующего подключения; чужая ревизия сохраняется.

Удерживается до 16 сессий и до 32 MiB текста: владелец, исходный запрос и черновик.
Один текст ограничен 8 MiB UTF-8. Повреждённые записи восстановления сохраняются
для ручного разбора; вместо записи в хранилище исходников запасной путь не используется.

Приёмка T101 проведена в установленном VSIX на Linux/VSCodium 1.109.5 в ru/en:
сохранение clean/dirty XML, один Undo/Redo владельца, целый пакет, два набора
СКД, два ручных списка формы, конфликт и восстановление после перезапуска.
Платформа 1С 8.3.27.2325 приняла изменённые XML СКД и списка: сборка CF,
повторная загрузка и выгрузка сохранили запросы. Выполнение запросов в ИБ
не проверялось. Windows, macOS, VS Code и Remote пока не проверены.


## Литерал BSL

Нужен `eska-project` с Metadata API 1.19 и включённым `querySessions.bslEditing`.
В модуле поставьте курсор внутри цельного строкового литерала и выберите в
контекстном меню **Редактировать запрос отдельно**. Имя переменной не имеет
значения. Конкатенация, шаблоны и вычисляемые выражения отклоняются с объяснением.

ESKA сохраняет полный текущий буфер модуля после решения штатного диалога IDE.
Вкладки родителя, включая защищённые и split-вкладки, заменяются SDBL-вкладкой без
`|` и удвоенных кавычек. Split-вкладки разделяют один черновик. У одного
владельца одна сессия; повторная команда возвращает в неё.

**Ctrl+S** и autosave сохраняют только черновик в private storage ESKA.
**Применить запрос к модулю** переносит литерал одной отменяемой правкой.
Модуль остаётся несохранённым. **Отменить редактирование запроса** закрывает
сессию и удаляет её черновик, сохраняя модуль. При закрытии изменённого
черновика можно применить его, сохранить для продолжения, отбросить или отменить
закрытие. Продолжение после перезапуска требует явного действия.

При закрытии dirty-вкладки родителя IDE сначала запрашивает сохранение,
отказ от сохранения или отмену. Отмена оставляет исходную вкладку и не открывает
запрос. ESKA фиксирует снимок после этого решения, не сохраняя модуль молча.
Пока открыт запрос, повторная навигация к родителю возвращает фокус запросу.
Применение, отмена, сохранение для продолжения и закрытие без изменений
возвращают исходный модуль и позицию курсора. Отмена закрытия оставляет запрос.
Сравнение владельца временно заменяет запрос просмотром без записи: слева снимок
ESKA, справа текущий native-буфер. Закрытие сравнения возвращает тот же черновик;
правка модуля через diff не предоставляется.

Перед применением ESKA проверяет точные версию и текст буфера, диск,
descriptor, поддержку и контекст.
При конфликте сохраняются оба текста; автоматической перезаписи нет. Новое
изменение модуля после preflight также останавливает применение. Успешное
завершение, отмена и ошибка снимают только ограничение сессии ESKA. Пользовательские
Native read-only overrides не меняются; запреты поддержки и файловой системы
не обходятся. Недоступность backend оставляет текст в IDE до переподключения.


## Анализ BSL-черновика

С Metadata API 1.20 и опубликованным `bsl-analyzer-app` 0.4.0 BSL-черновик
анализируется в текущем приложении. ESKA собирает в памяти полный модуль с новым
запросом и переводит позиции и правки; расширение использует уже работающий LSP.
Дополнительный файл, процесс или индекс на каждую правку не создаётся.

Проверены подсказки полей метаданных, псевдонимов и полей временных таблиц из
предыдущих запросов того же пакета, а также обновление диагностик синтаксиса.
Принятие подсказки меняет только SDBL-черновик. Hover, переход к определению и
ссылки передаются серверу; их покрытие определяется опубликованным анализатором.
Правки вне выбранного литерала, команды и snippets от completion не выполняются.

Статус во вкладке различает работающий BSL-контекст, построение индекса,
ограниченный самостоятельный контекст, приостановку и недоступный отчёт.
Пустой ответ во время загрузки не принимается за завершённую проверку.
Подсказки параметров запроса и контекст XML-владельцев в проверенном контракте
недоступны. СКД, основная таблица и зависимые поля списка остаются непроверенными.

Обычные языковые запросы к модулю-владельцу временно приостановлены: его позиции
могут отличаться от проекции. Другие BSL-модули продолжают анализироваться.
При изменении обычной вкладки владельца анализ черновика приостанавливается,
а LSP снова получает актуальный native-буфер. Отмена, применение и перезапуск
также восстанавливают обычную синхронизацию. Прежние ответы отбрасываются.
Смена приложения не переносит чужой resolver в ранее открытый черновик.

## Конструктор

В SDBL-вкладке выберите **Конструктор запросов**. Для выбора метаданных и
базовых структурированных операций нужен Metadata API 1.22, для возможностей
ниже — 1.23. API 1.21 сохраняет прежнее
редактирование выражений без каталога. Интерфейс организован по Конфигуратору:

- **Таблицы и поля**: слева база данных с поиском, в центре выбранные таблицы
  и их поля, справа поля результата. Двойной щелчок по таблице добавляет её
  в источники, по полю — в результат. **Добавить все поля** выполняется одной
  операцией и пропускает уже выбранные поля. Разворачивание таблицы показывает
  её табличные части; ESKA читает только запрошенный дескриптор.
  У регистра также доступны виртуальные таблицы; при выборе появляются
  позиционные параметры из сигнатуры ESKA, включая подсказки периодичности
  и метода дополнения. Пустое необязательное значение сохраняет свою позицию.
  **Добавить вложенный запрос** создаёт источник; его редактирование переводит
  ту же панель в дочернюю область. Родитель доступен после явного возврата.
- **Связи**: таблица, псевдоним, вид соединения, поля и сравнение задаются
  отдельными контролами. Изменение вида соединения сохраняет комментарии заголовка.
- **Группировка**: поля группировки и суммируемые поля с выбором агрегатной функции.
- **Условия**: левое поле, сравнение и правое значение/выражение. Несколько
  условий соединяются через `И`/`AND`.
- **Порядок**: поле/выражение и направление сортировки.
- **Объединения и псевдонимы**: копия выбранной ветки, переключение веток,
  сохранение/исключение дублей и удаление ветки. Выходные колонки добавляются,
  удаляются и переставляются согласованно; отсутствующее новое значение
  заполняется `NULL`. Порядок и итоги принадлежат всему объединению.
- **Итоги**: агрегатные выражения, общие итоги, группировки с иерархией
  либо заполнением периодов. Пустой список выражений означает автоматические
  итоги; удаление последней группировки убирает всю секцию.

Каталог использует выбранное приложение ESKA и объединяет объявления базы и
входящих расширений. Другие приложения не подмешиваются. Имена пользовательских
полей сохраняются, стандартные поля предлагаются в языке исходного запроса.
Бухгалтерский регистр с корреспонденцией получает раздельные счета и небалансовые
измерения/ресурсы дебета и кредита. Нумерованные субконто не приписываются обычной
таблице регистра. Без явно заданной базы внешний объект показывает ограниченный контекст.

Псевдоним нового источника при пустом вводе выбирает ESKA. При переименовании
существующего источника ESKA обновляет доказуемые ссылки, сохраняя строки,
комментарии и пути метаданных. Источники без `КАК`/`AS` используют полную квалификацию.
Для сложной строки доступно **Редактировать выражение**.
Регистры расчёта получают ресурсы графика и доступные базы через назначенные
планы видов расчёта. Переименование доказанного выходного поля обновляет ссылки
родителей и общий хвост; строки, комментарии и затенённые области сохраняются.
Порядок соединений по-прежнему не меняется без проверки зависимостей.

Разбор, допустимость операции, перенос комментариев и генерация минимальной
правки выполняются ESKA. Несовпадение числа полей веток блокирует применение
изменённого запроса. Неизвестный оператор, расширение СКД, `INTO`,
`HAVING`, несколько последовательных секций итогов и другие неподдержанные конструкции остаются точным исходным
текстом с объяснением недоступности. Полный пакет доступен в **Текст запроса**.
Конструктор проверяет структуру поддержанных изменений; семантическую корректность
выражения проверяет языковой сервер, если для этого владельца он доступен.
Вложенные области не получают общего порядка и итогов. Для старых API составные
запросы остаются непрозрачным текстом без новых операций.

Комментарии перемещаются с узлом. Перед удалением узла с комментарием нужно
выбрать перенос к оставшейся границе или удаление вместе с узлом. Отмена выбора
сохраняет предыдущий текст. Открытие и применение без операций сохраняют текст
и форматирование, включая неподдержанные части пакета.

Пока открыт конструктор, его черновик закреплён за одной ревизией в ESKA;
редактируемые split-вкладки заменяются панелью. **Применить к черновику**
возвращает ту же SDBL-вкладку с одной правкой Undo/Redo. Затем сохраните XML
либо явно примените BSL обычным способом. Сам конструктор не записывает владельца.
**Вернуться к черновику** или закрытие панели отменяет только непринятые операции
конструктора и возвращает ранее сохранённый черновик. В read-only доступен просмотр;
конструктор не выдаёт разрешение на запись.

Непринятые визуальные операции находятся в памяти backend. При аварии процесса
они теряются; подтверждённый до открытия панели черновик остаётся в private storage.
Вернитесь к нему, проверьте текст и явно продолжите сессию. При неподтверждённом
применении в Native-редакторе сохраняется последний текст для проверки; автоматически
переписывать XML/BSL конструктор не будет.

T104 проверена в установленном VSIX на Linux/VSCodium в ru/en: шесть разделов,
opaque-части пакета, комментарии, один Undo/Redo, dirty XML/BSL, read-only,
авария backend и настоящие кнопки webview. Выбор в диалогах комментариев в стенде
задан скриптом. Windows, macOS, VS Code и Remote остаются непроверенными.

Панели конструктора имеют изменяемую ширину, раскрытый текст — изменяемую
высоту. Разделители работают мышью и клавишами: Влево/Вправо для панелей,
Вверх/Вниз для текста. На узком окне каталог скрывается и возвращается кнопкой
**База данных**. Неиспользуемые дополнительные разделы доступны через
**Добавить раздел**. Размеры, раскрытие и прокрутка сохраняются в пределах
открытого конструктора, включая возвращение из вложенной области. Обновление
метаданных сохраняет ввод и курсор; состояние компоновки не содержит второй
копии текста запроса. Контракт backend не изменился: нужен API 1.30.

### Пакет и временные таблицы (API 1.26)

На вкладке **Пакет** укажите назначение `ПОМЕСТИТЬ/INTO`, добавьте запрос
или `УНИЧТОЖИТЬ/DROP`, удалите либо переставьте оператор. Пустое назначение
возвращает обычный результат. Поля индекса задаются списком `INDEX BY`.
Созданные ранее временные таблицы появляются в каталоге с проекцией создающего
запроса; поддержаны объединения, вложенные потребители и раскрываемые `*`.
После уничтожения прежняя проекция недоступна. Переименование сохраняет явные
псевдонимы и не затрагивает следующее создание одноимённой таблицы.

ESKA определяет области, время жизни и доказуемые зависимости; расширение
передаёт намерения и показывает результат. Новая известная ошибка отклоняет
всю операцию. Применение и отмена используют тот же черновик и штатный Undo/Redo.
`INDEX BY SETS` и `UNIQUE` сохраняются непрозрачными; добавление строк
в существующую временную таблицу пока вне визуального набора.

### Отбор по агрегатам (API 1.27)

На вкладке **Условия** есть отдельный раздел **Отбор по агрегатам (ИМЕЮЩИЕ)**.
Задайте выражение, сравнение и значение. ESKA создаёт `HAVING` после группировки,
различает ветки объединения и вложенные области; условия до группировки остаются
в прежнем `WHERE`. Доступны изменение, перемещение и удаление условий с прежними
правилами комментариев. Применение и отмена работают с тем же черновиком.

### Секция итогов и уровни группировки (API 1.30)

На вкладке **Итоги** добавьте секцию и задайте выражения и группировки.
Поддерживается одна секция с несколькими уровнями: платформа 8.3.27 отклоняет
повторное `ИТОГИ/TOTALS`. Добавление второй секции недоступно. Удаление последней
группировки убирает секцию, а пустой список агрегатов оставляет автоматические
итоги. Сохраняются общие итоги, иерархия, периоды и комментарии. ESKA вычисляет
владельцев строк и разрешения; расширение использует полученные индексы.
Несколько секций в исходном тексте сохраняются дословно без визуальной правки.

С API 1.29 вкладка «СКД» показывает узлы, позиции и разрешения ESKA. Поля,
дочерние поля, псевдонимы и бинарные условия передаются как значения DTO;
JavaScript не собирает фигурные скобки и запросы. Можно переключать
необязательность существующего JOIN и условность параметра периода виртуальной
таблицы, менять её отбор. Неизвестные блоки сохраняются. Обычные секции запроса
с расширениями СКД доступны только для чтения; основной текст меняется в
черновике после закрытия конструктора. Полную семантику проверяет платформа 1С.
