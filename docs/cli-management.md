# Выбор и совместимость backend


## Самостоятельный project

По умолчанию `eska.explorer.backend = "project"`: запускается `eska-project serve --stdio`,
проверяется identity `eska-project`, Metadata API 1.12 и capability
`analyzerConfiguration`, а также прежние capabilities дерева/свойств.
Полная ESKA и анализатор для дерева не требуются. Project и опубликованный
Analyzer устанавливаются и обновляются раздельно: [компоненты Explorer](component-setup.md).
Стандартное имя project ищется сначала в `~/.eska/bin`, затем в абсолютных PATH
entries; явный путь не имеет fallback. Project receipt и архив совместимы с
Python CLI T97. Пользовательский бинарник не перезаписывается. На 2026-10-21
публичный project ZIP ещё не опубликован; доступны локальная сборка/пакет T97.

## Явный legacy

`eska.explorer.backend = "legacy"` запускает `eska ide --stdio` с API 1.11.
Если стандартное значение executable не изменено, выбирается глобальная `eska`;
явный путь не переписывается. При успешном подключении выводятся предупреждение
и `ESKA Legacy v<version>`. Смена пути или режима отключает прежний процесс;
выполните перезапуск для нового подключения. Ниже описана установка и обновление
именно этого прежнего CLI.

Explorer использует общую ESKA текущего пользователя. Приватной копии CLI
в каталоге расширения нет. Поиск: абсолютные каталоги PATH по порядку, затем
`~/.eska/bin`. Относительные записи PATH не используются. Для SSH/WSL/контейнера
всё выполняется на стороне workspace extension host.

Для глобальной CLI проверяется версия не ниже 0.11.0. При подключении проверяются
IDE API major 1, minor не ниже 11, Designer XML, capabilities `propertyEditing`, `metadataRename`, `linkedPropertyEdits`,
`unsignedIntegerProperties`,
явное разрешение записи в handshake, отсутствие multi-context режима, поиск
и уведомления о файлах, а также лимиты протокола. Неподдерживаемый backend
не открывает проект. Самообновление — необязательная capability `selfUpdate`.

`eska.explorer.executable` позволяет использовать сборку для разработки.
При явно заданном пути подключение проверяет эту сборку и не требует совместимой
глобальной ESKA. При ошибке выбранного backend автоматической подмены на другой
файл нет. Значение `eska` включает обычный поиск глобальной установки.
После изменения пути нужно переподключиться. В режиме legacy проверка обновлений управляет
глобальной установкой независимо от выбранного backend разработки.

## Первая установка legacy

При отсутствии/несовместимости CLI Explorer предлагает **Установить ESKA
для пользователя**. До согласия выполняются только проверки версии и доступного релиза.
Новая установка скачивает официальный установщик выбранного стабильного релиза
из `1c-tooling/eska` и запускает его как задачу VS Code. Каталог — `~/.eska/bin`,
добавляемый установщиком в пользовательский PATH. Explorer также добавляет его
в PATH новых встроенных терминалов. Уже открытые внешние терминалы переоткройте.

## Обновление legacy

Команда **Проверить обновления ESKA** находится в меню `…` и палитре команд.
После подключения версия проверяется в фоне не чаще раза в сутки;
`eska.explorer.checkForUpdates = false` отключает эти проверки. Сетевая ошибка
фоновой проверки не отключает рабочее дерево.

Установка всегда требует нажатия кнопки. Поддерживающий обновление CLI сначала
вызывается с `update --check --format json`, затем с
`update --target-version <предложенная версия> --format json`.

Для старого CLI без `selfUpdate` первое обновление выполняется прежним способом:
Cargo определяется по реальному каталогу бинарника, `.crates2.json` и
`cargo install --list --root <root>`. Сохраняются root, target, profile и features;
предложенная версия должна быть опубликована также в официальном sparse index
crates.io (`index.crates.io`), без отметки yanked. Web API crates.io не требуется. Ошибка Cargo
не переключает установку на готовый бинарник. Для прочих установок используется
официальный установщик в `~/.eska/bin`, затем повторно проверяется PATH.

Процесс установки виден в терминале задач VS Code. На время операции Explorer
завершает своё IDE-подключение. После успеха проверяет реальный CLI и
переподключается. Отменить выполняющуюся установку можно через завершение задачи
VS Code; после ошибки доступны журнал и ручной перезапуск подключения.

Отключение отменяет также незавершённую проверку CLI перед подключением.
При обычном закрытии IDE расширение отменяет загрузки и служебные проверки,
завершает свою задачу установки и дожидается очистки временных файлов и lock.
Проверки версии и обновлений имеют ограниченное время работы; процесс,
игнорирующий штатное завершение, принудительно останавливается.

## Если обновление legacy не завершилось

- Несколько копий в PATH: первая имеет приоритет. Если после установки по-прежнему
  запускается старая копия, исправьте PATH и перезапустите редактор; расширение
  не удаляет посторонние копии.
- Ошибка Cargo/установщика: подробности находятся в терминале задачи. Следующей
  автоматической попытки установки нет. Универсального отката не обещается.
- Сообщение о занятой установке: дождитесь другой задачи. После аварийного
  завершения редактора может остаться `~/.eska/.explorer-install.lock`.
  Удаляйте его вручную только убедившись, что установка больше не выполняется.

Глобальная установка не изменяется тестами расширения: проверки используют
отдельный профиль VS Code и временный PATH с тестовой ESKA. Linux-подключение
проверено; реальная установка/обновление на Windows и macOS ещё требуют приёмки.
Обновление расширения пока выполняется новым VSIX из GitHub Releases.
