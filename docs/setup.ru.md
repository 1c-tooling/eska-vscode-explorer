# Подключение проекта к ESKA Explorer

По умолчанию используется `eska-project serve --stdio`, Metadata API 1.12.
В рабочей копии ESKA с этим package выполните `cargo build -p eska-project`,
затем задайте абсолютный путь к бинарнику в `eska.explorer.executable` на машине
проекта. Стандартное имя ищется сначала в `~/.eska/bin`, затем по абсолютным
каталогам PATH. Для дерева не требуются полная ESKA, Git, платформа 1С
или анализатор. [Выбор backend](cli-management.md).

Для подготовки доступна команда **Подготовить проектный и языковой компоненты**. В текущем публичном релизе нет project ZIP; используйте локальный бинарник или комплект T97. Актуальный стабильный релиз Analyzer устанавливается отдельно. [Установка компонентов](component-setup.md).

При открытии BSL Explorer запускает собственный языковой клиент; базовая подсветка
BSL/SDBL работает и без него. Отключение: `eska.explorer.languageFeatures = false`.
Настройка пути к серверу — `eska.explorer.analyzerExecutable`.
[Контекст, возможности и ограничения T86](language-service.md).

Для прежнего `eska ide` явно задайте `eska.explorer.backend = "legacy"`
и свой исполняемый файл `eska`. Путь сохраняется; Explorer показывает метку
Legacy и предупреждение. При несовместимости автоматической подмены файла нет.

Если у существующей выгрузки Designer XML нет `eska.toml`, выполните
`eska-project init` в её корне. Для каталога исходников, отличного от корня
или `src`, укажите `--source`. Поддерживаются `configuration`, `extension`,
`processing`, `report`. Команда не инициализирует Git и не запускает платформу.
В режиме legacy можно использовать `eska init` с параметрами этой CLI.

Проверьте манифест и выполните **ESKA Explorer: Перезапустить подключение**.
Расширение не инициализирует проект и не выполняет сборку 1С автоматически.

## Установка расширения

Установите VSIX через **Extensions → Install from VSIX…**.
Идентификатор — `1c-tooling.eska-explorer`. [Инструкция упаковки](packaging.md).

## Самостоятельное форматирование

Для CLI достаточно `eska-fmt`; общий вход `eska fmt` требует также `eska`,
а Explorer — `eska-project` с API 1.33. Анализатор устанавливается независимо.
Управляемые архивы используют `designer-xml-4`; контракты установленных ESKA
компонентов должны быть совместимы. Единый элемент ESKA открывает список компонентов
с версиями, путями и командами проверки обновлений и восстановления установки.
`eska.explorer.formatterExecutable` выбирает свой executable либо стандартный
поиск в управляемой установке/PATH. `eska.explorer.formatOnSave` по умолчанию
выключен. Стиль задаётся в `[format]` файла `eska.toml`; отступы редактора его
не переопределяют. При отсутствующем или несовместимом форматтере перехода на
анализатор нет. Для работы без сети отключите `checkForFormatterUpdates`
вместе с остальными фоновыми проверками.

## Подсказки многострочных аргументов

С `eska-project` API 1.34 продолжения строкового аргумента получают тот же
визуальный отступ, что и первая строка. Связанные подписи и прозрачные отступы
используют шрифт редактора для точного совпадения; независимые однострочные
вызовы сохраняют штатные подсказки. Исходный текст и настройки шрифта сохраняются.
Выравнивание действует при `editor.inlayHints.enabled = "on"`. Режимы по
клавишам-модификаторам, явная поддержка доступности и подсказки с действиями
или resolve сохраняют штатное отображение без выравнивания.
[Подробности](language-service.md#многострочные-аргументы-и-подсказки-параметров).
