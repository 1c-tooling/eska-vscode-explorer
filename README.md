# ESKA: 1C Explorer

Дерево метаданных 1С в VS Code и VSCodium: находите объекты по имени или синониму,
открывайте модули и XML, следите за изменениями исходников прямо в дереве.

Расширение работает с **Designer XML** через [eska CLI](https://github.com/1c-tooling/eska).
Поддерживает конфигурации, расширения конфигураций, внешние отчёты и обработки.

[Установка](#установка) · [Горячие клавиши](#горячие-клавиши) · [Настройки](#настройки) · [Подробное руководство](https://github.com/1c-tooling/eska-vscode-explorer/blob/main/docs/usage.md)

## Возможности

- **Все файлы в одном дереве.** Метаданные 1С, настройки проекта, README, сборки и остальные файлы, включая скрытые папки.
- **Структура как в Конфигураторе.** Группы и их порядок зависят от типа проекта.
  Конечные объекты отображаются без стрелки; пустота ветки подтверждается backend
  или результатом ленивой загрузки.
- **Модули под рукой.** Группа «Модули» идёт первой внутри объекта; общий модуль открывается нажатием на его имя.
- **Поиск по имени и синониму.** Находит объекты и вложенные элементы, в том числе в нераскрытых ветках.
- **Переход от файла к дереву.** Раскрывает нужную ветку и выделяет элемент, сохраняя открытый файл и несохранённые правки.
- **Сортировка объектов.** Кнопка на проекте включает алфавитный порядок всего дерева метаданных — групп и вложенных элементов; выбор сохраняется отдельно для каждого проекта.
- **Фильтр пустых разделов.** Скрывает пустые разделы корня и группы внутри «Общие»; выбор сохраняется отдельно для каждого проекта.
- **Подсветка Git.** Показывает изменения исходников цветами текущей темы и отмечает группы с изменениями внутри.
- **Предопределённые данные.** Отображает иерархию из XML и позволяет перейти к нужному элементу.
- **Работа с большими конфигурациями.** Ветки загружаются по мере раскрытия; изменения файлов обновляют затронутые части дерева.

Язык групп можно выбрать независимо от языка редактора. Иконки поддерживают
светлую, тёмную и контрастные темы.

## Установка

Понадобятся:

- VS Code или VSCodium с поддержкой API **1.109.0 или новее**;
- **eska CLI 0.11.0 или новее**, совместимый с IDE API **1.0** (можно установить из расширения);
- проект с `eska.toml` и исходниками в формате Designer XML.

### 1. Подготовьте CLI

Если ESKA уже установлена глобально, расширение использует её. При отсутствии
или несовместимой версии оно предложит кнопку **Установить ESKA для пользователя**.
Установка выполняется для текущего пользователя и доступна также из терминала.
Можно заранее установить CLI по [инструкции ESKA](https://github.com/1c-tooling/eska#установка).

Поиск идёт по PATH, затем в `~/.eska/bin`. Новая установка использует официальный
установщик и каталог `~/.eska/bin`; для новых встроенных терминалов расширение
добавляет каталог в PATH. Внешний терминал после первой установки переоткройте.

Настройка `eska.explorer.executable` предназначена для разработки: она выбирает
другой backend, но совместимая глобальная ESKA всё равно обязательна.
Передавайте только путь, без аргументов.

### 2. Установите расширение

Скачайте файл `.vsix` из Assets нужного
[релиза расширения](https://github.com/1c-tooling/eska-vscode-explorer/releases).
В редакторе откройте **Расширения → … → Установить из VSIX…** и выберите файл.

Идентификатор расширения — `1c-tooling.eska-explorer`.
Подробности установки и проверки пакета — в [инструкции VSIX](https://github.com/1c-tooling/eska-vscode-explorer/blob/main/docs/packaging.md).

### 3. Откройте проект

Откройте папку с `eska.toml`, предоставьте доверие рабочей области и раскройте
**ESKA: 1C Explorer** в проводнике. Если `eska.toml` ещё нет, настройте проект
через `eska init`: [инструкция подготовки проекта](https://github.com/1c-tooling/eska-vscode-explorer/blob/main/docs/setup.ru.md).

При успешном подключении справа в строке состояния появится `ESKA v<версия>`.
Подсказка показывает версию и путь к запущенному бинарнику. Нажатие проверяет
обновления общей установки ESKA.
Из нескольких независимых папок редактора выбирается одна; при открытии
рабочей области eska в дереве доступны её проекты.

## Рабочая область

Конфигурации отображаются непосредственно под **ESKA: 1C Explorer**. Внутри
конфигурации сразу идут «Модули», «Общие», «Справочники» и остальные разделы
метаданных — отдельной группы «Структура проекта 1С» нет.

Если у проекта есть собственный `eska.toml` внутри workspace, после метаданных
показываются его файловые группы. Общие файлы рабочей области находятся рядом
с конфигурациями, без дополнительного узла папки:

```text
ESKA: 1C Explorer
├─ Конфигурация
│  ├─ Модули
│  ├─ Общие
│  ├─ Справочники
│  ├─ …
│  ├─ Настройки проекта
│  ├─ Документация
│  └─ Прочие файлы
├─ Другая конфигурация
│  └─ …
├─ Настройки проекта
├─ Документация
└─ Прочие файлы
```

«Настройки проекта» содержит настройки ESKA, Git, BSL-анализаторов, редактора,
агентов и платформ размещения репозитория: например, `eska.toml`, `AGENTS.md`,
`.codex/`, `.vscode/` и `.github/`. Каталоги сохраняют внутреннюю структуру.
«Документация» — `README.md` и его языковые варианты. Остальное, включая
`build`, `.git/` и неизвестные скрытые папки, доступно
в «Прочих файлах». Настройки с одним корневым `eska.toml` находятся на общем
уровне, рядом с единственной конфигурацией. Файлы сохраняют настоящие имена;
пустые файловые группы не показываются.

Папки читаются при раскрытии. `Ctrl+K`, затем `E` (на macOS `Cmd+K`, затем `E`)
находит в дереве также настройки и другие файлы.
[Правила группировки](https://github.com/1c-tooling/eska-vscode-explorer/blob/main/docs/usage.md#файлы-рабочей-области).

## Навигация по исходникам

Пример ветки справочника:

```text
Конфигурация
└─ Справочники
   └─ Товары
      ├─ Модули
      │  ├─ Модуль объекта
      │  └─ Модуль менеджера
      ├─ Предопределённые данные
      ├─ Реквизиты
      ├─ Табличные части
      ├─ Формы
      │  └─ ФормаЭлемента
      │     ├─ Форма
      │     └─ Модуль
      ├─ Команды
      └─ Макеты
```

Выбор модуля открывает BSL. Выбор объекта или вложенного элемента открывает
его XML с выделением имени. Для общего модуля и некоторых других объектов
с одним модулем нажатие сразу открывает код, а описание доступно через
контекстное меню **Открыть XML**.

У формы есть отдельные узлы **Форма** и **Модуль**: первый открывает XML
содержимого формы, второй — её BSL. Это открытие исходников, без визуального
редактора форм. Модули показываются только при наличии BSL; двоичные `.bin`
не отображаются как исходники кода.

Пустые группы внутри объектов остаются видимыми. Кнопка фильтра у корня
конфигурации управляет только пустыми разделами корня и разделами внутри «Общие».

## Поиск

Нажмите лупу в панели дерева и введите часть имени или синонима.
Стрелками выберите результат, нажмите **Enter**, чтобы перейти к нему в дереве,
или **Escape**, чтобы закрыть поиск.

При первом поиске eska строит индекс в фоне. Пока он не готов, видны прогресс
и частичные результаты. Поиск не зависит от раскрытия ветвей; готовый индекс
используется повторно. Имена и синонимы ищутся без учёта регистра, без нечёткого
сопоставления. При слишком большой выдаче уточните запрос.

## Горячие клавиши

| Действие | Windows / Linux | macOS |
| --- | --- | --- |
| Показать открытый файл в дереве eska | `Ctrl+K`, затем `E` | `Cmd+K`, затем `E` |
| Поиск по дереву | `Ctrl+K`, затем `F` | `Cmd+K`, затем `F` |
| Обновить дерево при фокусе в нём | `F5` | `F5` |

После первой комбинации отпустите модификатор и нажмите букву.
Переход и поиск переопределяют стандартные сочетания только при фокусе
в редакторе файла подключённого проекта eska. Поиск также доступен при фокусе
в дереве. В остальных случаях сохраняются стандартные команды редактора.

Изменить или удалить назначения можно в **Сочетаниях клавиш / Keyboard Shortcuts**:
найдите команды по строке `ESKA Explorer`.

## Настройки

| Настройка | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `eska.explorer.executable` | `eska` | Глобальная ESKA или путь к backend для разработки |
| `eska.explorer.checkForUpdates` | `true` | Проверять обновления CLI не чаще раза в сутки |
| `eska.explorer.treeLanguage` | `auto` | Язык групп: `auto`, `ru-RU` или `en-US` |
| `eska.explorer.hideEmptyRootGroups` | `true` | Скрывать пустые разделы по умолчанию |

Переключение фильтра кнопкой сохраняет собственный режим проекта.
Действие **Использовать фильтр по умолчанию** возвращает применение настройки.
Имена объектов остаются такими, как в исходниках; выбор языка меняет подписи
групп и типов, а не содержимое конфигурации.

## Подсветка Git

Расширение использует статусы встроенного Git редактора и цвета текущей темы.
`M` обозначает изменение, `A` / `U` — добавленный или неотслеживаемый файл,
`R` — переименование, `D` — удаление, `!` — конфликт. Точка `•` на родительском
элементе означает, что внутри есть изменённые исходники.

Подсветка обновляется после сохранения файлов, добавления в индекс и коммита.
Код и XML формы отмечаются раздельно. Несохранённые правки сами по себе
Git-статус не меняют; состояние файла не означает изменение каждого свойства
внутри XML. Удалённые элементы, которых уже нет в дереве метаданных,
отдельными строками не добавляются.

Нужен включённый встроенный Git. Настройка `git.decorations.enabled` управляет
подсветкой; дополнительный опрос репозитория расширение не запускает.

## Обновления и совместимость

Расширение обновляется установкой нового VSIX из GitHub Releases.
Обновление CLI доступно через меню **… → Проверить обновления ESKA**.
После подключения выполняется фоновая проверка не чаще раза в сутки;
она отключается настройкой `eska.explorer.checkForUpdates`. Установка начинается
только после нажатия кнопки пользователя. Ход операции виден в терминале задач.

CLI с поддержкой самообновления вызывается через `eska update`. У старых версий
первое обновление выполняется через Cargo либо официальный установщик.
Для Cargo сохраняются прежний каталог и параметры установки; ошибка Cargo
не вызывает переход на установщик. После успешного обновления Explorer
переподключается. Подробности и ограничения — [управление CLI](https://github.com/1c-tooling/eska-vscode-explorer/blob/main/docs/cli-management.md).

Перед открытием проекта проверяются минимальная версия CLI **0.11.0**, версия
IDE API и обязательные возможности дерева, поиска и уведомлений о файлах.
Версии CLI и расширения не обязаны совпадать. Отсутствие возможности
`selfUpdate` допускается: оно требует первого обновления прежним способом.

Рекомендую использовать расширение вместе с [bsl-analyzer](https://github.com/itrous/bsl-analyzer).
Само ESKA Explorer не регистрирует язык BSL, отладчик, форматтер или анализатор кода. Настройки других расширений
и ассоциации файлов не изменяются.

Поддерживается только Designer XML. Поддержка формата EDT не планируется.
Встроенных команд сборки 1С, Git-операций,
редактора свойств и визуального редактора форм нет. XML и BSL можно редактировать
обычными средствами редактора.

Проверки выполнены на Linux с VSCodium. Приёмка Windows, macOS и Remote ещё
не завершена. Для SSH, WSL и контейнеров CLI должен находиться на машине проекта.
В браузерной IDE и виртуальной рабочей области расширение не работает.

## Если что-то не работает

Откройте меню **…** в заголовке дерева: там доступны выбор проекта,
отключение и **Показать журнал подключения**. Перезапуск подключения вынесен
в панель рядом с поиском и обновлением дерева.

Проверьте путь к CLI, наличие `eska.toml` и совместимость IDE API.
Если после изменения исходников ветка не обновилась, воспользуйтесь обновлением
дерева. Для точного перехода к имени внутри XML сначала сохраните его правки.

При [сообщении об ошибке](https://github.com/1c-tooling/eska-vscode-explorer/issues)
укажите версию редактора, расширения и CLI, ОС и шаги воспроизведения.
Приложите относящийся к сбою фрагмент журнала; он может содержать пути к проекту.
